# Decisions: Shot Resolution Integrity

- Date: 2026-10-26
- Status: Confirmed (사용자 버그 수정 요청과 실제 재현에 근거한 기술 결정)
- Scope: React 실제 플레이의 비접촉 피해·중복 발사 완료·스테이지 전환 정합성. 게임 수치·보상·방어·지역 장애물 효과는 유지.

## D01. 실제 접촉까지만 일반 사탕 피해
- `node tmp/remote-hit-probe.mjs` red: 눈1/seed0/각도7.5°/파워.95, 모든 장애물 toppled. 사탕 endpoint x907.91인데 x1330의 뒤 적도 hitIds에 포함되어 두 적에 각각4 피해.
- 원인: planShot의 장애물이 없는 분기에서 impactDistance는 첫 적으로 자르면서 resolvedHits는 전체 경로의 모든 적을 전달했다. 일반 사탕은 첫 접촉만, 창만 실제 경로에서 최대3 관통한다.
- 물리 shotMeta가 있는 엔진 입력에도 일반 직접 피해는 첫 대상까지만 방어적으로 제한한다. 장애물 연쇄 피해는 별도이며 유지.

## D02. 발사 완료의 단일 처리
- `node tmp/duplicate-shot-probe.mjs` red 2회: 동일한 빗나간 발사 완료 재전달 시 accepted:true, 체력95→90, 두 번째 반격. 세션에 물리 발사의 고유 식별자/소비 이력이 없었다.
- 실제 UI에서 중복 콜백이 발생하는 특정 원인은 아직 입증되지 않았다. 이 재현은 세션 경계가 중복 완료를 막지 못함을 입증한다. 정상/취소/resize/hidden/round 이동 브라우저 검증으로 UI와 함께 잠근다.
- 세션이 beginShot에서 현재 배치·생존 적·강화를 기준으로 canonical(화면과 전투가 공유하는 단일) 궤적을 확정하고 shotId/encounterId를 발급한다. fireShot은 그 식별자와 저장된 결과로 한 번만 확정한다. UI 전달 hitIds는 물리 발사의 권위가 아니다.
- UI 취소는 해당 예약만 무효화하며, 이전 발사의 완료/취소가 다음 발사나 다음 라운드를 건드리지 못한다. 기존 순수 엔진 단위용 abstract fireShot은 metadata 없는 호출로 유지하되 pending 물리 발사 중에는 거부한다.

## D03. 유지할 정상 예외
- 바람궁수의 실제 유도 궤적, 숲 통나무의 실제 적 충돌, 도시/혼돈의 범위 피해는 직접 명중과 다르지만 기존 확정 기능이므로 유지한다. 진단에서 이를 일반 사탕의 원격 명중과 구분한다.
- 피해는 엔진에서 한 번, 리뷰2초/반격/보스 분리는 표시만. 적이 남아 있으면 클리어하지 않는다. 새 발사 없이 추가 반격·탄약소모·진행 없음.
- 기존 HTML 목업과 out.json은 이번 React 수정 대상으로 포함하지 않는다.
