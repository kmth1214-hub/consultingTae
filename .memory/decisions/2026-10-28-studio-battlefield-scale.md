# Decisions: 관리자 전장 오브젝트 크기 확대

- Date: 2026-10-28
- Status: Confirmed

## D01. 적용 범위
- **Chosen**: 로컬 관리자 `/__dev/maps`의 숲·눈·도시·혼돈 미리보기와 테스트 플레이에 먼저 적용한다. 사용자 게임과 Azure 배포판은 검토 전까지 기존 크기를 유지한다.
- **Rationale**: 넓은 맵에서 전투 대상을 알아보기 쉽게 만들고, 관리자 화면에서 전 지역의 전투 구도를 검토할 수 있다.

## D02. 크기와 충돌 판정
- **Chosen**: 쿠키·새총·일반 몬스터의 월드 크기를 현재의 1.5배로 키우고 충돌 판정도 표시 크기에 맞춘다. 보스는 확대된 일반 몬스터 기준 3배, 혼돈 융합 보스는 4.5배 비율을 유지한다.
- **Rationale**: 화면에서 보이는 크기와 맞히거나 맞는 범위가 일치해야 한다.

## D03. 사탕과 장애물
- **Chosen**: 사탕과 지역별 장애물도 월드 크기를 1.5배로 키운다. 발사·장애물·적 충돌, 낙하, 구름 거리를 바뀐 크기에 맞춘다. 구름 거리의 기존 규칙인 사탕 지름 최대 5배는 유지한다.
- **Rationale**: 새총·캐릭터와 전투 물체의 비율을 유지하고, 보이는 접촉과 실제 판정이 맞도록 한다.

## D04. 화면 구도와 배치 제약
- **Chosen**: 현재 3600 단위의 넓은 전장과 시작 시 전체 조망을 유지한다. 확대된 몬스터·장애물·발사대가 겹치거나 맞힐 수 없는 배치가 되지 않도록 관리자 시범판의 배치 검증을 함께 조정한다. HUD는 화면 좌표로 유지한다.
- **Rationale**: 사용자가 원하는 광활한 맵을 보존하면서, 확대된 전투 요소를 읽고 조준할 수 있어야 한다.

## Code findings for planning
- `src/game/battlefieldModel.js`: 전장 크기, 캐릭터·새총·몬스터·장애물 크기, 충돌 원형, 사탕 반경을 정의한다. 일반 몬스터의 기존 크기는 적 수에 따라 92 또는 60이다.
- `src/game/battlefieldPlacement.js`: 같은 배치를 미리보기와 실제 전투에 제공하며 모든 적·장애물을 맞힐 수 있는지 검증한다.
- `src/dev/createStudioSession.js`: 관리자 전용 시범 세션을 만들고 숲 시범 기능과 지역별 몬스터 시범 기능을 켠다. 크기 배율은 이 기능들과 독립적으로 전달해야 한다.
- `src/components/Slingshot.jsx` 및 `src/game/shotGeometry.js`: 그림 내부의 시위 위치와 월드 발사 좌표를 함께 맞춰야 한다.
- `src/components/ProjectileFlight.jsx`: 일부 구름 회전·그림자 표현이 전역 사탕 반경을 사용하므로 관리자 배율을 반영해야 한다.
