# Decisions: 관리자 맵 2.5D 재구성

- Date: 2026-11-02
- Status: Confirmed
- Scope: 로컬 `/__dev/maps`의 지도 미리보기와 테스트 플레이. 일반 사용자 게임과 Azure 배포 화면은 이번 작업의 적용 대상이 아니다.
- Related: [기존 관리자 전투 깊이 장식](./2026-10-31-studio-battlefield-depth.md), [지역 레이어와 지도 스튜디오](./2026-10-21-regional-layered-world-and-map-studio.md)

## D01. 적용 화면과 지역
- **Chosen by user**: 관리자 지도 미리보기와 테스트 플레이에만 재구성 맵을 적용한다.
- **Carried forward from prior decisions**: 숲·눈·도시·혼돈 네 지역을 같은 깊이 기준으로 다룬다. 일반 게임은 기존 맵을 유지한다.
- **Rationale**: 실제 게임에 반영하기 전에 로컬 관리자 화면에서 장면을 비교하고 검토한다.

## D02. 표현 방식과 시점
- **Chosen by user**: 기존 일러스트 분위기의 2.5D 레이어로 지형, 길, 건물·나무 등의 풍경을 재구성한다. 현재의 가로형 옆모습 구도를 유지하면서 길의 윗면·측면과 배경 레이어로 깊이를 표현한다.
- **Rationale**: 새총 전투의 화면 구도와 지역별 그림체를 지키면서 맵 자체에 입체감을 준다. 단순한 그림자·원근 보강이나 실제 3D/WebGL 전환은 이번 선택이 아니다.

## D03. 전투 좌표와 판정
- **Chosen by user**: 이번에는 시각적 입체감만 재구성한다. 조준, 탄도, 충돌, 적·장애물 배치를 유지한다.
- **Code-derived constraint**: 전투 월드는 3600×1200 좌표와 `groundY=900`을 사용한다. 장면의 새 윗면·측면·접지 표현을 월드 좌표에 맞추고, 시차를 받는 배경 장식과 실제 충돌 물체가 어긋나지 않게 한다.
- **Rationale**: 맵 디자인 검토와 전투 규칙 변경을 분리한다.

## D04. 원본 일러스트와 새 제작 범위
- **Chosen by user**: 지역별 색감과 주요 랜드마크는 유지한다. 길·중경·전경은 입체감이 드러나도록 다시 제작한다. 하늘·원경과 기존 자산은 필요에 따라 재사용한다.
- **Code-derived constraint**: 현재 네 지역 모두 하늘·원경·중경·길·전경을 분리해 렌더링한다. 숲은 단일 전용 레이어 자산, 나머지 지역은 동·서 패널 자산을 사용한다. 관리자 테스트 플레이에는 길 단면·접지 그림자용 `StudioDepthScene`과 원본 비교 버튼이 이미 있으나, 지도 미리보기에는 이 깊이 장식이 없다. 새 자산과 장면은 같은 스튜디오 미리보기·테스트 플레이에 일관되게 나타나야 한다.
- **Rationale**: 기존 지역의 정체성을 보존하면서 단순 장식 추가보다 분명한 맵 재구성을 제공한다.

## D05. 검토와 경계
- **Implementation judgment from confirmed scope**: 기존 관리자 테스트 플레이의 원본 비교 기능을 재구성 맵과 연동하고, 지도 미리보기에서도 원본과 재구성 맵을 비교할 수 있도록 계획한다. 지역·레이어 표시, 이동·확대, 전투 테스트 기능을 유지한다.
- **Acceptance**: 네 지역의 관리자 미리보기와 테스트 플레이에서 길의 윗면·측면, 중경·전경의 거리감, 물체의 접지가 일관되게 보인다. 발사대·쿠키·적·장애물 및 조준선의 가독성이 유지된다. 원본과 전환해 차이를 확인할 수 있고 일반 게임의 화면·전투 판정은 바뀌지 않는다. 넓은 맵의 양 끝과 카메라 확대·이동 상태에서도 빈 경계나 반복 티가 나지 않아야 한다.
- **Access boundary**: `/__dev/maps`는 Vite 개발 모드에서만 열린다. 로컬 관리자 화면의 활성화는 개발 서버 실행으로 처리했고, 배포 사이트 관리자 인증은 이번 작업에 포함하지 않는다.
